# GUI NEXT · 页面与视觉规格

日期：2026-10-06。依据：保留的 v2 CURRENT、当前 TUI R1、真实公开投影与用户的简洁原则。

## v2 的保留与调整

保留深灰底色、苔绿点缀、细分隔线、个人知识生态的关系表达。GUI 采用代码已有的 Inter 正文字体语义，减少满屏等宽字体和大写技术文案。旧 CURRENT 中的首页大树、边缘重复笔记卡片、About 标签墙与遥测面板、Tools 全量盒子网格不直接搬入 NEXT。

GUI 背景 `#151614`、表面 `#1A1B19`、正文 `#E2E1DD`、次要文字 `#A8A9A4`、分隔 `#2C2D2A`；苔绿调整为 `#A4B66C`，用于当前入口、链接与少量层级。选中表面 `#242A1E`。在 Figma 定义独立 `Dual UI / GUI` 样式，不覆盖 TUI 或 CURRENT 的 token。

字体层级以 14/16/18 为主要阅读尺寸，24/32/48 只用于少量标题。桌面 1440×900、手机 390×844。顶栏仅品牌、Search、Access；底部为主导航和模式切换。正文限定宽度，既不满屏拉伸段落，也不靠空卡片填补留白。

底部语境使用真实路径（Tools 分类保留 `#services` / `#hosts` 等），不重复站点品牌；有选中对象时追加对象名称。Git / 版本只使用真实构建信息，空间不足时收入详情，不为填空虚构值。手机下方主导航独占一行，上方显示语境与模式选择。

## Home

第一层：BakerSean、个人数字生态、一句说明。第二层：Library / Projects / Tools 三条用途明确的入口。第三层：Blog 和 Notes 分开陈列真实示例，再提供少量常用服务。

移动端将入口排成可点击的纵向行，保留写作类型的名称。生态关系通过内容的组织表达，不以难以读懂的大图作为唯一导航。首页不展示虚构统计或服务健康。

## About

将作者与实践放在前面，使用短段落说明“我在做什么”。背后的 Thought Forest、Personal Digital System、Personal Infrastructure 作为解释生态关系的旁注，不升级为控制面板。

桌面正文与生态说明分栏；手机顺序阅读。GitHub、Friends、知识标签为低负担的文本入口。真实实现应保留完整内容并允许内部滚动，首屏稿不是删掉未显示段落的授权。

## Tools

保留 Services / External / Hosts / Network 的共同分类，GUI 用“服务、外部资源、主机、网络”帮助识别。搜索名称/用途与筛选按钮共处一条工具栏；筛选计数和已选条件只在需要时出现。

默认服务列表以名称、简短用途、一个主动作组成。桌面右侧显示当前所选对象的说明、访问与关系；手机优先显示用途和可点击入口，完整详情在下一层，不把大段预览挤在每行下面。

服务示例来自实际公开投影：LiteLLM、Nezha Panel、Sub-Store、Personal Twin、Hermes、Infrahub。LiteLLM/Sub-Store 等标记 Access；哪吒存在公开入口。原型的选定条目是展示节选，不等于完整目录总数；不把 active 写成 ONLINE。

外部资源使用相同的行语法，主机与网络以“查看”进入公开详情。生命周期、服务宿主等保持可获取，但不在默认列表中堆叠多个标签。

## TUI 对照与切换

TUI 保留已认可的编号 Tab、I 文本筛选、F 分组筛选与底部对象路径。在现有 R1 屏幕加入 GUI 切换目标，GUI 可以返回相同模块与类别的 TUI；原型展示的是固定示例状态，不替代代码对任意筛选/对象状态的恢复实现。

Figma 继续 MODULE × REVISION MATRIX。三个模块的 NEXT cluster 内，左侧保留 TUI Desktop/Mobile，右侧为 GUI Desktop/Mobile；Tools 各类别纵向排列。CURRENT、LEGACY、Product Map 与 Product Definition 不改变。

## 可复用部件与限制

本轮收敛：固定页壳、主导航、模式选择、单行资源项、所选详情、搜索/筛选栏、文本入口。原型由原生文字与 Frame 构成，使用共享样式与 Auto Layout 组织内容，未导入整页截图。

社区 MCP 未提供创建任意组件实例的接口。现有组件库可参考并复用样式，组合视图保持可编辑；不能把普通 Frame 副本称为已绑定的组件实例。正式代码只抽取重复且稳定的部件，不创建两个独立应用。

本轮在 Components 的 WORKING 区存放四个原生主组件草稿：资源默认行、资源选中行、模式选中态、Tab 默认态。基础板与部件板用于审查；完整状态集、实例绑定和变量绑定仍需后续收敛，不能按完整生产组件库验收。
