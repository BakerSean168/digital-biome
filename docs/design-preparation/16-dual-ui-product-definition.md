# TUI / GUI · 同一站点的两种界面

日期：2026-10-06。状态：用户批准先优化 Figma 原型与系列文档，应用双界面代码尚未实施。

## 新决定

Digital Biome 同时提供 TUI 与 GUI。GUI 从重构前 v2 的 Basalt & Moss 视觉基础继续优化；TUI 保留当前的对象浏览和键盘交互。两者都是当前产品的界面模式，不向用户称为旧版/新版，也不是部署协议里的 Release v2/v3。

这项决定替代 10-version-coexistence.md 中“不并行维护”的产品方向，但不恢复两份独立部署、独立内容或独立权限实现。历史文档保留作为决策演进。

## 不变的产品语义

站点是个人数字生态的展示、分享和日常使用入口。“掌控”意味着知道自己拥有什么、用途是什么、如何进入使用；不等于加入 CRUD、CMS 或运维控制台。

两种模式共用 Home、Library、Projects、Tools、About 入口。Notes 是持续修订的知识笔记，Blog 是独立写作，两者在数据、列表和阅读语义上保持分离。Tools 的 Services、External、Hosts、Network 分类一致，不因切换模式换一套术语。

共用真实数据投影、搜索索引、路由、服务目标、Access 和外部新标签页规则。模式切换不授予权限，也不会显示第二套未经公开审核的数据。GUI 仍采用上部内部滚动、底部导航固定的布局。

## 两种模式分别优化什么

| 模式 | 优先任务 | 表达 |
| --- | --- | --- |
| TUI | 日常快速定位、筛选、键盘移动和关系跳转 | 等宽字体、紧凑行、快捷键提示、对象路径 |
| GUI | 了解作者、阅读内容、辨认服务用途、直观点击 | 自然正文排版、较宽行距、明确动作、必要时展示详情 |

GUI 不是删除功能后的轻量站；TUI 也不是管理员模式。差异在呈现与入口层级。高级筛选仍可通过明确按钮进入，GUI 无需在每个标签前显示数字或命令键。

## 简洁性的判断标准

每个区域先回答一个问题：我在哪里、这里有什么、下一步能做什么。不要通过更多卡片、徽标、颜色、状态和统计数字填满空间。

默认不展示：假在线状态、UPTIME、示例节点总数、凭空的版本/提交号、标签墙、费用/订阅仪表盘、私人运行数据、管理按钮。生命周期是目录事实，只有它影响访问判断时才进入第一层；详细宿主关系放在所选对象详情。

v2 的生态树是视觉历史参考，新的 GUI 用可读的入口关系表达生态含义。首页不要求用户先理解或操作一幅图才能进入知识和工具。

## 本轮设计范围

Home、About、Tools 三个模块。Tools 展示服务、外部资源、主机、网络四种状态；每种都有 Desktop/Mobile。与对应 TUI 状态建立模式切换路径。

Library、Projects、阅读详情等模式延展规则写入后续计划，不能因为主导航已有这些名称便声称 GUI 全站完成。Figma 中未制作的 GUI 路由不偷偷跳回 TUI。
